¿Qué construye el DOM?

El DOM es la estructura que arma el navegador con el HTML. Aunque el código esté medio mal escrito, el navegador intenta acomodarlo para poder mostrar la página. O sea, va cerrando etiquetas, acomodando elementos y formando el árbol del documento como puede.

¿Entra en Quirks Mode?

Sí. Como el código no tiene <!DOCTYPE html>, el navegador entra en Quirks Mode. Básicamente es como un modo viejo donde algunas cosas pueden verse raro o comportarse diferente.

¿Qué se ve en pantalla?

Se ve el texto “Hola mundo” en negrita y luego aparece “Segunda línea”. La página se muestra, pero no significa que el código esté bien. Solo significa que el navegador lo medio arregló para que no se rompa todo.

Conclusión

Aunque el navegador ayuda y corrige algunas cosas, no hay que confiarse. Lo mejor es escribir bien el HTML desde el inicio y siempre poner <!DOCTYPE html>.

Actividad 2 - HTML Semántico

El div.header se cambia por header porque representa el encabezado de la página.

Los enlaces se meten dentro de nav porque sirven para navegar entre secciones.

El div.main se cambia por main porque ahí está el contenido principal.

El post usa article porque es contenido que puede entenderse por sí solo.

Los tags van en aside porque son información extra, no el contenido principal.

El título principal se cambia a h1 porque representa el tema principal de la página.

El div.footer se cambia por footer porque es el pie de página.

En resumen, se cambia el montón de div por etiquetas que sí dicen qué significa cada parte.

Actividad 3 - Elementos y Flujo

blockquote es un elemento de bloque y semántico. Se usa para citas largas de otra fuente.

span es un elemento en línea y no semántico. Sirve para aplicar estilo a una parte pequeña del texto.

strong es en línea y semántico. Se usa para marcar algo importante.

article es de bloque y semántico. Sirve para una noticia, post, tarjeta de producto o publicación independiente.

b es en línea y presentacional. Solo pone el texto en negrita, pero no le da importancia real.

time es en línea y semántico. Sirve para fechas y horas.

ul es de bloque y semántico. Sirve para listas sin orden, como características o un menú.

mark es en línea y semántico. Sirve para resaltar una palabra clave o resultado importante.

code es en línea y semántico. Sirve para mostrar un fragmento de código.

section es de bloque y semántico. Sirve para dividir una página en partes como servicios, contacto o sobre nosotros.

Actividad 4 - Formularios

Se usa POST porque la información del usuario no debería verse en la URL.

El enctype normal es application/x-www-form-urlencoded porque no se están subiendo archivos.

Cada campo debe tener un label para que sea más fácil saber qué hay que escribir y también para mejorar accesibilidad.

El carné usa pattern para aceptar solo formatos como IS123456.

fieldset y legend ayudan a ordenar el formulario por grupos, como datos personales o datos académicos.

Se usa caption para ponerle un título o descripción a la tabla.

Actividad 6 - Multimedia

¿Qué atributos del sandbox necesita el iframe para que el mapa funcione?

El mapa necesita allow-scripts para poder ejecutar el JavaScript que usa Google Maps. También puede necesitar allow-same-origin para que el contenido funcione como espera Google. Sin esos permisos, el mapa puede cargar mal o quedarse en blanco.

¿Por qué el video tiene dos etiquetas source y no solo un src?

Porque no todos los navegadores aceptan los mismos formatos. Por eso se ponen dos source, por ejemplo MP4 y WebM. Así el navegador escoge el que sí puede reproducir.

¿Qué pasa si una imagen no tiene alt?

Si una imagen no tiene alt, una persona que usa lector de pantalla no sabe qué muestra esa imagen. Además, si la imagen no carga, tampoco aparece una descripción útil.
