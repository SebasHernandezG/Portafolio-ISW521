Pregunta3:

Esto significa que en el github hay cambios que aun no tienes en la rama local que estés trabajando y git no deja subir porque podrías sobrescribir el trabajo de tu compañero o equipo.

Flujo correcto:

git fetch origin
git rebase origin/main
git push origin main

si hay algún conflicto 

git add .

git rebase --continue

git push origin main

con force:

git add .

git rebase --continue

git push --force-with-lease origin main  y se usa solo en ramas personales porque si es en equipo pasa que borras el trabajo del compañero o equipo

Justificación Para que ocurra un fast-foward main tendria que ser un ancestro directo del propio feature/user.profile es decir no tener commits propios despues del punto de divergencias  ya que git necesita crear un commit merge que una los dos arboles.

Pregunta2:

para revisar los cambios se realizarían la siguiente listas de comandos 

```bash
# 1. Traer cambios remotos sin hacer merge
git fetch origin

# 2. Ver commits de la rama remota
git log origin/feature/dark-mode --oneline

# 3. Ver diferencias entre main y la rama del compañero
git diff main origin/feature/dark-mode

# 4. Ver qué archivos cambiaron (resumen)
git diff --stat main origin/feature/dark-mode

# 5. Ver detalle de un commit específico
git show b2f8
git show d7e3

```
